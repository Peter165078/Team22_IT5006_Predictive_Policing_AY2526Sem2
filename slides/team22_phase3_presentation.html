Why This Problem

Motivation and Project Framing

  • Police resources are limited, so timing and location awareness matter.
  • We focused on decision support, not automated enforcement.
  • Our prediction target is deliberately modest: does at least one crime incident occur in a given space-time unit?
  • This framing lets us compare models fairly and keep the system aligned with available pre-event information.
Project scope
  • Phase 1: literature review, EDA, dashboard.
  • Phase 2: data preparation, feature engineering, model training, evaluation.
  • Phase 3: repository cleanup, demo packaging, final presentation, final report handoff.
Key framing sentence for the project: given observed features X for a location and time, estimate the probability that crime occurs, rather than predicting exact crime details after an event already happens.

Data and Pipeline

From Raw Records to a Reproducible Modeling Dataset

Data Scope

We used Chicago crime archives already split by year and sampled 20,000 rows per year from 2022, 2023, and 2024 for a reproducible local benchmark.

Feature Engineering

We built temporal, spatial, and historical features, including hour, day-of-week, cyclic encodings, district, beat, coordinates, grid cells, and rolling crime history windows.

Evaluation Logic

We applied chronological train-validation-test splits, train-only fitting for preprocessing, and later record-level plus spatial-temporal evaluation.

Label construction

The source data contains observed crimes only, so we constructed explicit negative labels by sampling district-day combinations with no observed incident in the sampled positive set. We present this clearly as a modeling approximation, not as naturally observed negative ground truth.

Rolling windows

7d, 14d, 30d, and 90d were chosen to represent weekly, biweekly, monthly, and quarter-scale recency patterns instead of arbitrary cutoffs.

Main takeaway

HistGradientBoosting is the strongest record-level benchmark, but it does not dominate by a large margin. Random Forest stays close, and Decision Tree slightly improves over Logistic Regression.

Why that matters

Our final story is more credible because we avoid overselling small metric differences. The benchmark supports model comparison, not claims of dramatic predictive superiority.

Spatial and Temporal Evaluation

Temporal Patterns Are Learnable; District Ranking Is Weak

Hourly correlation

  • Logistic Regression: 0.827
  • Decision Tree: 0.931
  • Random Forest: 0.976
  • HistGradientBoosting: 0.972

All four models capture short-term daily timing patterns reasonably well.

District-level hotspot overlap on test split

  • Logistic Regression: top-10 overlap 0.5
  • Decision Tree: top-10 overlap 0.5
  • Random Forest: top-10 overlap 0.3
  • HistGradientBoosting: top-10 overlap 0.2

Aggregate spatial performance does not follow the same ranking as record-level AUROC.

Honest conclusion: our system is more useful for timing-sensitive risk awareness than for claiming a strong district-wide hotspot ranking. This became one of the most important lessons from milestone feedback.

Interpretation

What Drives Predictions?

Feature importance of the best model

The clearest evidence for what the model actually uses: hour, cyclical hour features, district identity, and rolling recent counts.

Hourly crime rhythm

A visible daily cycle explains why temporal features dominate prediction quality.

Best-model feature importance
  • Temporal features contribute about 65.9% of grouped permutation importance.
  • Historical features contribute about 20.1%.
  • Spatial features contribute about 14.0%.

Top signals for HistGradientBoosting are hour, hour_sin, District, crimes_last_30d, and crimes_last_14d.

So the clean interpretation is: timing is the dominant signal, recent local history adds meaningful value, and district identity still helps anchor the model geographically.

Spatial context still matters, but it plays a supporting role compared with temporal rhythm and recent history.

This is also why the model transfers better on temporal alignment than on cross-jurisdiction spatial ranking in NIBRS.

Interpretation should stay descriptive, not causal. We can say temporal rhythm is the strongest predictive pattern in our benchmark, but we should not claim this explains the social causes of crime.

Limitations and Responsible Use

What We Would and Would Not Claim

What works

  • Clear EDA story
  • Interactive dashboard
  • Reproducible model pipeline
  • Reasonable timing-pattern learning

What is limited

  • Sampled benchmark only
  • Constructed negative labels
  • Weak district aggregation performance
  • No full fairness audit

Responsible framing

  • Decision support, not automation
  • Human review stays in the loop
  • Need policy, fairness, and threshold review before real deployment
Final recommendation: use the system for scheduling support, localized triage, and human-in-the-loop prioritization, not for deterministic operational decisions.
